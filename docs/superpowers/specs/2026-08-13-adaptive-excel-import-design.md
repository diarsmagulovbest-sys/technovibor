# Адаптивный импорт Excel без ИИ

Дата: 2026-08-13

## Цель

Заменить импорт по фиксированному шаблону на детерминированную систему, которая распознаёт структуру прайс-листов разных поставщиков без использования ИИ. Система должна автоматически обрабатывать понятные файлы и требовать подтверждения администратора только для неоднозначных полей.

## Критерии успеха

- Обрабатываются все товарные листы книги, а служебные листы пропускаются.
- Строка заголовков может находиться не в первой строке.
- Названия колонок могут отличаться у разных поставщиков.
- Цена, название и идентификатор определяются по сочетанию заголовка и профиля значений колонки.
- Категории из названий листов и строк-разделителей сохраняются.
- Основные характеристики техники извлекаются из описания регулярными правилами и словарями.
- Перед записью показывается результат анализа и примеры товаров.
- Неоднозначные критические поля требуют подтверждения; ошибочный импорт не выполняется молча.
- Подтверждённые настройки поставщика используются при следующих загрузках похожих файлов.
- В системе отсутствуют обращения к моделям ИИ и внешним сервисам распознавания.

## Выбранный подход

Используется гибридная модель: автоматическое распознавание с оценкой уверенности и ручным подтверждением только спорных полей.

Полностью автоматический импорт отклонён, потому что числовые колонки цены, остатков, гарантии и валютных значений могут быть похожи. Полностью ручное сопоставление отклонено из-за неудобства при регулярных загрузках.

## Поток пользователя

1. Администратор выбирает файл `.xlsx` размером до установленного лимита.
2. Сайт отправляет файл на анализ без изменения каталога.
3. Экран предварительного просмотра показывает:
   - найденного поставщика;
   - включённые и пропущенные листы;
   - найденные таблицы и строки заголовков;
   - сопоставление колонок;
   - выбранное правило цены;
   - количество товаров, предупреждений и пропущенных строк;
   - несколько нормализованных примеров.
4. Если уверенность по критическим полям высокая, доступна кнопка «Импортировать».
5. Если поле неоднозначно, оно подсвечивается и администратор выбирает правильную колонку из списка. Остальные уверенно найденные поля не требуют настройки.
6. После подтверждения сервер повторно проверяет анализ и атомарно обновляет каталог.
7. Подтверждённое сопоставление сохраняется как профиль поставщика и применяется к следующим похожим файлам.

## Архитектура

### 1. Чтение книги

Модуль чтения возвращает все листы как матрицы значений и ограниченные метаданные. Он не решает, где находятся товары, и не записывает данные в базу.

### 2. Поиск таблиц и заголовков

Для каждого листа анализируется начальная часть и повторяющиеся заполненные области. Каждая строка получает баллы за:

- известные синонимы заголовков;
- несколько непустых ячеек;
- наличие текстовых и числовых колонок ниже;
- повторяемую структуру последующих строк.

Служебные листы отбрасываются, если на них нет устойчивой товарной таблицы. Повторный заголовок внутри длинного листа распознаётся и пропускается.

На первом этапе поддерживается одна основная товарная таблица на листе с любым количеством строк-разделителей и повторных заголовков.

### 3. Определение ролей колонок

Роли определяются по двум независимым источникам:

- нормализованному заголовку и словарю синонимов;
- профилю значений: тип, доля заполнения, уникальность, длина текста, диапазон чисел, наличие валюты и шаблоны идентификаторов.

Поддерживаемые роли первой реализации:

- внешний идентификатор товара;
- артикул;
- код производителя;
- название;
- описание;
- бренд;
- цена в локальной валюте;
- альтернативная или специальная цена;
- наличие;
- гарантия;
- поставщик;
- категория.

Критическими считаются название, действующая цена и стабильный идентификатор. Остальные роли могут отсутствовать.

### 4. Правило цены

Приоритет цены определяется явно и показывается в предварительном просмотре:

1. специальная или акционная цена в тенге, если она положительная;
2. дилерская или обычная цена в тенге;
3. другая колонка цены в тенге с высокой уверенностью.

Колонки в долларах не пересчитываются автоматически без явно обнаруженного курса и подтверждённого правила. Числовая колонка не признаётся ценой только по величине: требуется ценовой заголовок или подтверждение администратора.

### 5. Классификация строк

Каждая строка относится к одному типу:

- товар;
- категория или подкатегория;
- повторный заголовок;
- служебный текст;
- пустая строка;
- ошибочная товарная строка.

Строка товара должна содержать название, положительную цену и идентификатор либо данные для безопасного резервного идентификатора. Строка с одним текстовым значением перед группой товаров считается разделителем категории и распространяется на последующие товары до следующего разделителя.

Категория верхнего уровня берётся из названия листа. Подкатегория берётся из строки-разделителя.

### 6. Идентификация товаров

Приоритет идентификатора:

1. код производителя;
2. артикул поставщика;
3. внешний ID товара;
4. стабильный хеш из нормализованных бренда, модели и названия.

Резервный хеш помечается как идентификатор низкой уверенности. При возможных дублях импорт блокируется до подтверждения.

### 7. Определение поставщика и профиля файла

Поставщик определяется по сохранённому профилю, домену и названию компании внутри книги, названию прайс-листа или имени файла. Если однозначного значения нет, администратор вводит название один раз.

Профиль поставщика содержит:

- отпечаток структуры заголовков;
- выбранные роли колонок;
- правило цены;
- включаемые и исключаемые листы;
- способ определения категорий;
- дату последнего подтверждения.

Профиль не привязывается к номерам колонок без проверки заголовков, поэтому перестановка колонок не ломает импорт.

### 8. Извлечение характеристик без ИИ

Характеристики извлекаются из названия, описания, категории и отдельных колонок с помощью нормализации текста, словарей и регулярных выражений.

Для ноутбуков и компьютеров первая версия извлекает:

- семейство и модель процессора;
- объём оперативной памяти;
- тип памяти, если указан;
- объём и тип накопителя;
- модель или семейство видеокарты;
- диагональ и разрешение экрана;
- операционную систему.

Для комплектующих распознаются тип товара и доступные профильные параметры, например сокет, количество ядер, частота, объём памяти или накопителя. Нераспознанный текст сохраняется в исходных данных и остаётся доступным поиску.

Правила характеристик имеют версию. Повторная обработка может обновить атрибуты без повторной загрузки прайса.

### 9. Оценка уверенности

Каждое сопоставление получает числовую уверенность и объяснение. Итоговый режим определяется минимальной уверенностью критических полей:

- высокая: можно импортировать одним нажатием;
- средняя: требуется подтвердить выделенные поля;
- низкая: импорт заблокирован до ручного сопоставления.

Уверенность не скрывается за общей надписью: интерфейс показывает, почему поле было выбрано и какие альтернативы найдены.

## Хранение данных

Существующие товары и предложения сохраняются. Схема расширяется следующими сущностями:

- нормализованная категория и подкатегория товара;
- структурированные атрибуты товара;
- профиль импорта поставщика;
- временный анализ загрузки с ограниченным сроком жизни;
- диагностический отчёт импорта.

Оригинальная строка продолжает храниться в `raw_json`. Поиск индексирует название, артикулы, бренд, категорию, описание и распознанные характеристики.

## API и безопасность

Импорт разделяется на два действия:

- `analyze`: проверяет файл и создаёт предварительный результат без изменения каталога;
- `commit`: принимает подтверждённое сопоставление и применяет ранее проанализированный файл.

Оба действия доступны только авторизованному администратору. Сервер не доверяет данным предварительного просмотра от клиента и повторно валидирует сопоставление. Запись выполняется через staging-импорт; активный прайс поставщика переключается только после полного успеха.

## Обработка ошибок

- Файл без товарных таблиц возвращает понятное сообщение и список проверенных листов.
- Листы без товаров пропускаются и отображаются в отчёте.
- Строки с некорректной ценой не загружаются и показываются с номером листа и строки.
- Дубли идентификаторов, неоднозначная цена и отсутствие названия блокируют подтверждение.
- Ошибка одного поставщика не должна частично заменять его активный прайс.
- Предыдущий активный прайс остаётся доступным при любой ошибке нового импорта.

## Приложенный контрольный файл

Файл `price 10.08.2026.xlsx` используется как обязательный интеграционный пример.

Ожидаемое поведение:

- лист `Главная` пропускается;
- распознаются 11 товарных листов;
- строка заголовков находится на строке 4;
- строки серого разделителя становятся подкатегориями;
- `Спец.тенге` используется при наличии положительного значения, иначе `Дил. тг.`;
- `D3` и `Спец.цена` не принимаются за цену в тенге;
- `Наличие` сохраняется как остаток;
- поставщик определяется как `VSTrade`;
- характеристики ноутбуков извлекаются из `Описание`;
- до подтверждения анализа каталог не изменяется.

## Тестирование

### Модульные тесты

- нормализация заголовков и синонимов;
- поиск строки заголовков;
- профилирование колонок;
- выбор действующей цены;
- классификация строк;
- наследование категорий;
- формирование стабильного идентификатора;
- извлечение характеристик;
- расчёт уверенности.

### Интеграционные тесты

- приложенный реальный файл;
- фиксированный старый шаблон;
- переставленные колонки;
- заголовок после служебных строк;
- несколько листов и повторные заголовки;
- файл без артикула;
- файл без цены;
- конкурирующие числовые колонки;
- частично повреждённые строки;
- повторная загрузка файла того же поставщика.

### Проверка интерфейса

- выбор файла;
- отображение анализа и примеров;
- исправление одного спорного сопоставления;
- блокировка импорта при критической ошибке;
- успешный импорт с обновлением каталога;
- удобство на мобильном экране и с клавиатуры.

## Границы первой реализации

- Поддерживается `.xlsx`; старый бинарный `.xls` не поддерживается.
- Не выполняется OCR изображений и сканов внутри книги.
- Не обещается безошибочное автоматическое распознавание полностью безымянных колонок; такой файл переводится в режим подтверждения.
- Валютная конвертация не выполняется без отдельного подтверждённого правила.
- Правила характеристик сначала покрывают компьютеры, ноутбуки и наиболее распространённые комплектующие; исходное описание сохраняется для дальнейшего расширения.
